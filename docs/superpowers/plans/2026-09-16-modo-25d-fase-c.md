# Modo 2.5D · Fase C — fichas, luces, «ver como» y niebla por jugador

> **For agentic workers:** un implementador fresco por tarea + revisión (spec + calidad) tras cada una; test en rojo → código → verde → `npm run check` → commit.

**Goal:** Las fichas y luces de JA-VTT (`objects` de tipo `token`/`light`) se ven y se mueven en el mapa 2.5D con los sprites del diorama; cada jugador ve sólo lo que ven sus personajes; la niebla explorada se guarda por usuario y escena.

**Architecture:** No hay modelo nuevo de fichas: el motor consume `S.tokens`/`S.lights` del estado de JA-VTT y los traduce a celdas (`x = cx*CELL+CELL/2`). Los movimientos salen como `ops` normales tras comprobar bloqueo en cliente. La visión por celda del diorama (`vision.js`) toma como observadores las fichas que el usuario controla (o todas si es director en vista Director). El explorado por celda (`Uint8Array n*n`) se guarda en la tabla `fog` con `cx=cy=0`.

**Spec:** `docs/superpowers/specs/2026-09-16-modo-25d-design.md`. **Previo:** fases A y B.

## Global Constraints

- `sanitize` (rules.js) es la única validación de `token`/`light`; campos nuevos: `token.art` (string ≤ 40, clave de `CHAR_INFO` o id de `images`), `light.mount` (`{cell:int≥0, dir:0..3}` o ausente). Sin ellos, el 2D no cambia.
- Reglas de jugador intactas (`playerUpsert`): mueve su ficha, abre puertas, nada más. El servidor **no** valida rutas ni bloqueos (igual que 2D).
- Niebla: tabla `fog` existente; en 2.5D una sola fila por (escena, usuario) con `cx=0,cy=0`, `data` = `n*n` bytes (0 no explorado, 255 explorado, 128 «recordado»). `fogreset` la borra igual que en 2D.
- Fichas ocultas/`hidden` y planos: filtrado del servidor como hoy; ocultación por LOS: cliente.
- Sin dependencias nuevas; test primero; `check` + `test:ui` verdes.

### Task C2: sprites desde `S.tokens` / `S.lights`
**Interfaces:** `chars.js`: `syncTokens(list)` donde cada item `{id,x,y,kind,name,color,hidden,vision,sight,darkvision,light,art,owner,size}` → `G.chars` con `c.id`; celda `cx=Math.floor(x/CELL)`, `cz=Math.floor(y/CELL)` (CELL=50 llega por `opts.cell`). Si `art` no está en `CHAR_INFO`, usa `kind==='enemy'?'goblin':'knight_f'` (arte propio: fase D). Fichas con `light.on` → `setCarried`. `syncLights(list)`: luces sueltas con `mount` → `addLight(preset, cell, mount)`; presets de JA-VTT se mapean a los del diorama (`LIGHT_PRESETS` comunes: candle, torch, lantern, magic, crystal; `bullseye/campfire/brazier/moon/daylight/window/custom` → el más parecido por radio; tabla explícita en `chars.js`).
- [ ] Tests (regex + módulo puro `public/js/d3/light-map.js` importable en Node con la tabla de presets: test comprueba que todos los `LIGHT_PRESETS` de `rules.js` tienen entrada).
- [ ] `index.js`: `syncObjects()` lee `window.S` (clásico) → `syncTokens(S.tokens)`, `syncLights(S.lights)`; `net.js` lo llama tras cada `applyState`/`applyOps` cuando `is25()`.
- [ ] Implementar → verde → commit `feat(2.5d): fichas y luces del tablero como sprites del diorama`.
